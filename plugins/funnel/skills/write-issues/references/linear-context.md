# Gathering Context for a Linear Issue

Gather only enough context to write:

- A direct problem statement
- The selected type's assignment: acceptance criteria, prototype and feedback, research questions, or concept to refine
- Useful evidence, constraints, and pointers
- Appropriate metadata and relationships

Use the referenced issue or project first. Expand to comments, parent or child issues, and related work only when
needed to fill one of those sections.

Look specifically for:

- The underlying problem, excluding proposed solutions
- Intended results, questions, or concepts to refine
- Technical constraints or relevant code references
- Scope boundaries and dependencies
- Existing project, parent, label, or priority conventions

Existing Linear initiatives, projects, and issues are evidence that help create an actionable issue that matches the
user's intent. They are not templates unless the user says otherwise. Surface material conflicts rather than resolving
them silently.

Stop once there is enough context to draft the selected type's issue format. Summarize what was learned and ask about
conflicts or gaps that prevent a confident draft.
