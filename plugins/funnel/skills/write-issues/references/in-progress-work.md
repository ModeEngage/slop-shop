# Documenting Completed or In-Progress Work

Use the permanent implementation format and write the issue around the full deliverable, not the most recent change.

- State the problem as it exists without relying on the work status to explain it.
- Include every required outcome in Acceptance Criteria, whether the work is complete or remains to be done.
- Keep Implementation Details focused on evidence, constraints, and remaining work.
- Keep independently deliverable prerequisites in separate issues and record the appropriate relationship.
- Reference an authoritative related issue instead of copying a long requirement list when the issue remains
  understandable without the duplicated detail.

Add one status section only when it helps the reader distinguish completed work from remaining work:

- `## Completed Work` when all listed work is complete
- `## Completed / In Progress Work` when the status is mixed
- `## In Progress Work` when work has started but none is complete

Use a flat list of pull requests or other durable artifacts. Describe the significant outcome of each item. Group items
only when many artifacts span distinct work areas or phases. Do not list temporary planning documents or unrelated
prerequisites as completed work.
