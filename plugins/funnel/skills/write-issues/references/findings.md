# Recording Exploratory Findings

Use for prototype, research, and interview assignments. Include the following requirements in the issue so the executing
agent has an explicit record of where results belong.

- Record findings in a Markdown document and attach it to the Linear issue. Keep the original assignment intact.
- Include the type-specific evidence: artifact links and feedback for prototypes, answers and sources for research,
  or the confirmed synthesis for interviews.
- If the issue belongs to a project, check the current project description for an explicit reference to this issue.
  When one exists, update that entry with a short finding or outcome and a link to the issue. Preserve unrelated content.
- Keep detailed findings in the attached document. The project entry provides enough context for later agents to judge relevance.
  Do not add an entry solely because the issue belongs to the project.

For example, an existing project entry can become `[Issue title](issue-url): short summary of the finding`.

These are requirements for execution of the assignment, not instructions to publish results while drafting it.
When updating findings on an existing issue, follow [update-existing-issue.md](update-existing-issue.md). Before updating
a project description, fetch its current content and preserve unrelated edits. Resolve conflicting changes before writing.

Verify that the Markdown document is attached and accessible before treating the recording step as complete.
